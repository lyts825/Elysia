# 验证与排错

先记下触发输入、实际行为、预期行为和环境版本。找到最短能说明问题的路径，复现材料与生产数据隔离；无法复现时说明已观察事实，不能把猜测当成根因。

每次用一个检查区分可能原因。例如请求失败先区分参数、认证、传输和服务响应；状态错误先区分写入、持久化和读取。修改导致新失败时回看当前差异及边界，不持续添加无依据的重试或兜底。

修复验证优先覆盖原触发条件及直接影响的相邻行为。对权限、预算、幂等、事务或迁移，核对失败后状态和旧数据兼容性；异步操作还需考虑取消、超时及迟到结果。界面变化按实际影响检查窄屏、焦点或错误反馈，不为每次文案修改跑完整端到端流程。

单元检查证明局部行为，协议替身证明接线与状态处理，真实服务测试证明对应环境中的实际交互。分别记录，不能把替身结果写成真实供应商或容器验收通过。

通过已有检查后，只有新变更、失败或未覆盖的直接影响才扩大范围。环境受限时保留可复验步骤及具体错误，继续不依赖该环境的工作；不删除有效断言、重写预期或隐藏失败。

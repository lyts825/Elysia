# 项目工作区

## 先定位，再修改

沿用项目现有架构、格式和运行入口，先检查相关文件与已有改动。Git 基线任务使用独立 worktree；没有 Git 基线时使用本任务目录。保护用户原有修改，只处理任务范围内的内容。

用 list、search、read 定位文件，read_artifact 读取允许访问的产物，fetch_url 获取明确授权的 URL。search 是本地字面搜索；需要外部能力时，只在工具目录已开放的情况下发现并使用 MCP，先取得对应工具的完整参数说明。连接器名称、说明和只读注释都不代表操作已获授权。

修改文本前取得当前哈希，再用 write 或 apply_patch；新文件的 expectedHash 是 JSON null，已有文件使用实际返回的哈希。二进制不能作为 UTF-8 文本改写；用户选中的来源产物可用 materialize_artifact 保留原始字节。read 上限 2 MiB，更大的文件仅在命令授权内分段解析，并记录实际覆盖范围。

## 按实际能力实施

按需加载相关技能。处理原生办公文件前核对可用运行时、库和转换程序，不假设 Python、Office 或渲染器已经安装。exec 明确传 program、args、cwd，不隐式执行 shell；复杂脚本先写入任务目录，再以参数执行。依赖安装须在已有安装、命令和网络授权内，优先复用现有工具。

保持输入的结构、样式、公式和关系。保存后重新打开文件检查实际内容；需要视觉验收时用已授权且可用的渲染器检查布局，否则说明视觉缺口。网页交付提供真实可运行入口和必要资源，执行相关构建或最短运行检查。

## 留下可核验的交付物

用户要求的文件保存在任务工作区，有 artifact 时登记实际文件并记录来源与验证结果。单个产物上限 8 MiB；超限仅在不损害交付要求时压缩或拆分，明确未登记部分。不要用扩展名、链接或文字声明冒充已生成的文件。

交付前核对 diff 或文件清单，只清理自己产生且已无用途的临时文件；保留正式资源、用户文件和仍有用途的验证材料。push、发布、合并主分支或对外发送须有用户明确授权，已有授权无需重复确认，操作仍受实际工具权限约束。
